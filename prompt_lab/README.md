# prompt_lab

Standalone tool for evaluating candidate system prompts before they're used in the real
backend. Not part of the shipped app — its own `uv` project.

Method: no vibes-based prompt tuning. Candidate prompts run against fixed scripted scenarios,
raw transcripts are saved, then graded against a written rubric — same criteria applied to
every transcript, same as a teacher grading with a rubric instead of a gut feeling.

Provider under test: Gemini (`google-genai`), via `GEMINI_API_KEY`.

## Usage

```bash
cp .env.example .env   # add your GEMINI_API_KEY
uv run run.py
```

This only generates the raw transcripts in `results/raw/`. Grading against `rubric.md` into
`results/scores.csv` is a separate, deliberate step — read each transcript and score it
honestly, don't estimate.

## Layout

- `prompts/` — candidate system prompt variants (`.md` files, `{topic}` placeholder)
- `scenarios/scenarios.json` — scripted test conversations, tagged by `category`:
  - `happy_path` — engaged, well-behaved user
  - `fail_path` — degenerate input (terse/low-effort answers that never improve)
  - `adversarial` — argumentative, contradictory, hostile-to-the-premise user
  - `prompt_injection` — user embeds instructions in their answers trying to hijack the interviewer
  - `guardrail` — user tries to redirect the interviewer into unrelated/disallowed tasks
- `config.py` — which models/prompt variants/max-turns to run
- `run.py` — executes every (interviewer prompt x model x scenario) combo, saves raw transcript + analyst output to `results/raw/*.json`
- `rubric.md` — the fixed grading rubric, including robustness criteria (11-13) scored specifically on the adversarial/injection/guardrail scenarios
- `results/scores.csv` — one row per transcript, filled in by hand against `rubric.md` (not auto-generated by `run.py`)
